# Security policy

## Reporting a vulnerability

Do not include private keys, sensitive DealEnvelopes, or exploit details in a public issue. Use GitHub's private vulnerability reporting for this repository when available. If that channel is unavailable, open a minimal issue asking the maintainer to establish a private contact channel without disclosing the vulnerability.

## Supported version

The public beta supports protocol and implementation version `0.1.x`. It has not received an independent security audit.

## Security scope

Reports are especially useful for signature bypass, canonicalization mismatch, replay across signature domains, receipt forgery, key exposure, unauthorized evidence disclosure, resource exhaustion, and verification differences across runtimes.

Commercial disputes, identity proof, authority, legality, fairness, delivery, and truth of submitted terms are outside the protocol's security claims.
